# 07 Anomaly detection: requirements

- R1. (Superseded in part by R1b and ADR 0008.) Inputs: the feature 05 feature table (`keyframe.experiments.load_feature_table()`), using the physics and rolling-std/slope columns plus raw sensor channels chosen by `features.FEATURE_SETS["raw+physics+rolling"]`. Excluded columns never enter. NaNs are imputed with the training fold's healthy medians.
- R1b. Two input arms (ADR 0008): `raw`, as R1 (already run), and `residual`, the primary: `HealthyEngineResiduals` fitted on the training fold's healthy rows, then the detector sees every `resid_` column, every `phys_` column and every rolling `_std` and `_slope` column; never raw levels, rolling means, or the residual inputs (Engine Speed, Water Brake Weight, Fuel Flow). `keyframe.anomaly.detector_inputs(df, arm)` returns the column list and a function to build the fitted view; a test asserts the residual arm contains no raw level column.
- R2. `keyframe.anomaly` defines detectors with `fit(X_healthy)` and `score(X)` (higher = more anomalous), all standardising with statistics from the training fold's healthy rows only:
  - `IsolationForestDetector` (sklearn, 300 trees, seeded, `max_samples` up to 8,192)
  - `PCADetector`: PCA keeping 95% of healthy variance; score = Hotelling T² and Q (SPE) combined as the max of each divided by its 99th percentile on training healthy rows (report T² and Q separately too)
  - `AutoencoderDetector`: `MLPRegressor` with a bottleneck (e.g. hidden layers (64, 16, 64)), trained to reconstruct standardised healthy inputs, early stopping, seeded; score = mean squared reconstruction error
- R3. Fitting uses only rows with label Normal in the training loads. A spy test proves no fault row and no held-out-load row is seen in `fit`. For the healthy-only detectors, the reference file's rows of the held-out load are also excluded (main score); nothing here uses the shop-test variant.
- R4. Experiment `uv run python -m keyframe.experiments anomaly --detector <iforest|pca|autoencoder> --fold <bin> [--inputs raw|residual]` (default `raw`, keeping the existing file names) writes per-row scores for the held-out fold to `data/processed/experiments/anomaly_<detector>_fold<bin>.parquet` for raw and `anomaly_<detector>_residual_fold<bin>.parquet` for residual (index, run, load_bin, label, t, score, and for PCA the T² and Q parts), under 9 minutes per invocation; skips existing unless `--force`. Rows may be thinned for fitting only (every 2nd row per run), never for scoring.
- R5. For both arms (an `inputs` column in the results): AUROC (healthy vs any fault) pooled over folds and per fold; per fault class AUROC (that class vs healthy); both reported with fold spread.
- R6. Thresholds: for each fold, the threshold is the score quantile that gives a 2% false alarm rate on the training fold's healthy rows (chosen without the held-out load). Then feature 06's `keyframe.alarm.sustained_alarm`-style logic (an alarm needs the score over threshold for every row of a trailing window of `min_duration_s`, chosen from {30, 60, 120, 300} on the training fold's own runs by lowest median delay with a 2% alarm-level false alarm budget; reuse `keyframe.alarm.detection_delay` and `alarm_metrics` by expressing the detector alarm as an `alarm` column of "Anomaly" or "Normal") gives detection delay per run and the alarm-level false alarm rate on held-out healthy rows.
- R7. Notebook 05 leads with the residual arm, shows the raw arm as the comparison and the reason for ADR 0008, and presents AUROC table and ROC curves (`05_roc.png`), per-class AUROC, detection delay per run (`05_detection_delay.png`), score traces around switch-on for one run per fault (`05_scores_switch_on.png`), and compares detection delay with the classifier's from notebook 04. It states the brief's targets (AUROC 0.95, delay 10 min) as met or not met, and opens with the findings.
