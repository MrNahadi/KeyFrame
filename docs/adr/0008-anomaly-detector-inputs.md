# 0008. Anomaly detectors run on load-normalised inputs; raw inputs kept as the comparison

Status: accepted
Decided-by: planner (inferred), recorded before the residual-input detectors were run
Question: Feature 07 (T-004): the healthy-only detectors on `raw+physics+rolling` score a pooled AUROC of 0.50 to 0.56 on held-out loads. Which inputs should the detectors use?
Decision: The primary detector input is the load-normalised view: healthy-engine residuals of every sensor channel (`keyframe.features.HealthyEngineResiduals`, fitted on the training fold's healthy rows only), the physics features, and the rolling standard deviations and slopes; no raw levels, no rolling means of raw levels, and not the residual model's own inputs (speed, brake load, fuel flow). The raw-input detectors already run stay in the report as the comparison. The choice is made on engineering grounds before seeing the residual results, and both are reported whatever they show.
Basis: A detector trained on healthy running at three loads sees any new load as unfamiliar, so healthy rows at the held-out load score as high as faulty ones; the per-fold AUROCs (0.45 to 0.78) with pooled values near 0.5 show exactly that offset. The brief's premise for residuals: "a model trained on the reference file predicts each sensor from speed, brake load and fuel flow, and the classifier sees how far each reading sits from that prediction". Ranked trade-offs 1 and 2 (honest evaluation, engineering credibility) favour pre-declaring the primary arm over picking whichever scores best.
Consequences: Feature 07 adds an `--inputs residual|raw` option to the anomaly experiment and reports both arms. Notebook 05 leads with the residual arm and states the raw arm's result as the reason for the choice. The feature 05 caveat applies: the degree-2 healthy-engine model is least reliable at the 40% edge of the load range.
