# 0006. `raw+physics+rolling` with LightGBM, unpruned, goes forward to modelling

Status: accepted
Decided-by: answerer (inferred), per ADR 0003's fully-automatic working agreement
Question: T-008 (05-features), R15: which feature set (pruned or not) goes forward to modelling?
Decision: `raw+physics+rolling` x LightGBM, unpruned, is the feature set for modelling. Physics ratios and rolling statistics earn their place; healthy-engine residuals and pruning do not, on this evidence:
1. Ranked by pooled macro F1 (the headline target, R15) on the leave-one-load-out ablation (`reports/results/03_ablation.csv`), `raw+physics+rolling` x LightGBM tops the table at 0.617 (accuracy 0.712), ahead of every residual-based combination (best residual arm, `residuals+physics` x logreg: 0.608).
2. Pruning `raw+physics+rolling` x LightGBM inside the training folds (R13, `reports/results/03_pruning.csv`) drops the pooled macro F1 to 0.558, with a wide per-fold spread (0.263 to 0.785). The correlation/permutation-importance filter removes correlated physics/rolling columns that still help even at grouped-zero marginal importance on this arm. Pruning does not earn its place for this feature set.
3. The shop-test score (R9, R14) for the best *residual* arm, `residuals+physics` x logreg, is worse than its main score (pooled macro F1 0.587 vs 0.608). The false alarm rate on Normal rows splits cleanly by source and fold (`03_feature_engineering.py`, shop-test section): reference-row false alarms at the 40% fold rise from 1.7% to 60.7% when the shop-test's extra reference rows (down to 56 kW) are fed to the residual fit, and pre-fault-row false alarms at 40% rise from 33.4% to 95.0%. The 60/75/85% folds barely move. Every pre-fault healthy row at the 75% fold is flagged even in the main score (100%), consistent with notebook 01's finding that the two 75% runs are cold test-day outliers, independent of the residual step.
Basis: R15 fixes the ranking rule (pooled macro F1, then per-class recall and false alarm rate as tie-breakers) before the numbers are read, so the winning arm needs no tie-break. The shop-test result is reported honestly per T-008's Notes rather than tuned or explained away: the damage is real and concentrated in the 40% fold, where reference rows near the low end of the operating range reshape the degree-2 healthy-engine polynomial at the edge of its training range. This affects only the residual arms, which are not the chosen feature set, so it does not block this decision, but it is recorded for feature 06.
Consequences: Feature 06 builds the pipeline from `features.FEATURE_SETS["raw+physics+rolling"]` with LightGBM, and does not prune. If a later feature revisits healthy-engine residuals, it should first try restricting the residual model's training rows to the 40-85% operating range (dropping the reference file's sub-40% rows) or a lower-degree polynomial fit, per T-008's notes, before re-evaluating the shop-test.
